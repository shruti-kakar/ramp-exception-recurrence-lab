# Where every number comes from

Someone looking at the app sees a repeat rate of 63%, a prevention index of
2.02 for missing PO, a projected $724 a year. None of those are measurements.
This file traces each one back to the line of code or the external source it
came from, so a reviewer can agree or disagree with a specific number instead
of the app in general.

Three kinds of claim appear in this project, and they are not interchangeable:

| Kind | Example | Where it's checkable |
| --- | --- | --- |
| **Computed** | "63% of exceptions are repeats" | Arithmetic on the dataset. Re-derive it, don't trust it — see §1 |
| **Assumed** | "Missing PO is 80% fixable" | The author's judgement call, not measured. See §2 |
| **Cited** | "Ramp supports configurable approval policies" | An external page, linked in §3 |

## 1. The synthetic dataset

Every exception record is generated by [`src/generate_data.py`](src/generate_data.py)
from a fixed seed (`RANDOM_SEED = 20261026` in [`src/config.py`](src/config.py)).
Nothing is sampled from a real company, Ramp, or JPMorgan. The generator's own
docstring says so. Running `make data` reproduces the exact file bundled with
the app, byte for byte.

The structure baked into the generator is what the rest of the app then
"discovers." That's worth being blunt about: this isn't evidence that real
exception data looks like this, it's the scaffolding the prototype needed to
have something to rank.

| Parameter | Value | File | What it controls |
| --- | --- | --- | --- |
| `N_EXCEPTIONS` | 300 | `config.py:88` | Total rows in the bundled dataset |
| `MONTHS` | 6 | `config.py:89` | Window the dataset spans |
| `CAUSE_WEIGHTS` | 29/24/19/16/12% | `generate_data.py:32` | How often each root cause occurs, chosen to echo the review-effort split in the original case-study brief |
| `CHRONIC_PAIRS` + `CHRONIC_SHARE` | 9 pairs, 46% | `generate_data.py:107,126` | A deliberately concentrated set of vendor/cause combinations that recur — this is what makes a "worklist" possible at all |
| `MINUTES_PROFILE` | per cause, e.g. duplicate invoice ~41 min | `generate_data.py:52` | Hands-on reviewer time per exception type, the author's estimate of relative effort, not a timed study |
| `REOPEN_RATE` | per cause, 6%–22% | `generate_data.py:61` | How often a resolved case reopens, used to compute the headline reopen metric |
| Bill volume growth | `base=1180`, ×1.06 per month, ±6% noise | `generate_data.py:209` | The denominator for "per 1,000 bills" rates — picked to resemble a growing mid-market AP team, not drawn from any real company |

## 2. Modelling assumptions

These live in one file, [`src/config.py`](src/config.py), each with an inline
comment explaining its source. They are the numbers most worth arguing with,
and the ones a real pilot (see `CASESTUDY.md` §5) would replace first.

| Assumption | Value | Rationale as written in the code | Where it's used |
| --- | --- | --- | --- |
| `MIN_CLUSTER_SIZE` | 2 | A pair only counts as "recurring" on its second occurrence | Every repeat/addressable-pool calculation |
| `FIXABILITY_PRIOR` | missing_po 0.80, vendor_details 0.70, gl_coding 0.65, approval_routing 0.55, duplicate_invoice 0.35 | Author's estimate of how much an upstream control could remove, from AP workflow experience — **not validated with any Ramp customer or operator** | Prevention index, scenario projections |
| `DEFAULT_REVIEWER_HOURLY_COST` | $48/hour | "Rough US AP-analyst midpoint" — a round-number estimate, adjustable in the app's sidebar | Converts hours to dollars in the scenario tab |
| `HOURS_PER_FTE_MONTH` | 160 | Standard full-time month | FTE-equivalent figure |
| `SENSITIVITY_BAND` | ±50% | Applied around every point estimate so no single number is quoted alone | Every banded projection |
| `DEFAULT_REDUCTION_PCT` | 10% | "Deliberately modest" starting point for the prevention slider | Scenario tab default |
| `TOP_VENDORS_FOR_CONCENTRATION` | 3 (`analytics.py:29`) | "Roughly the number of vendor-specific fixes one AP admin can own in a month" — a judgement call, named rather than buried | Concentration score |
| Power-check constants | z=1.96 (α=0.05), z=0.84 (80% power) | Standard two-proportion z-test thresholds (`scenario.py:131`) | Pilot sample-size calculation |

## 3. External resources

What Ramp's product actually does is cited, not assumed. Two tiers:

**Directly verified in this repository's research** (fetched and checked
during this project):

- [ramp.com/accounts-payable](https://ramp.com/accounts-payable) — Ramp's own
  Bill Pay / AP product page
- [support.ramp.com/managing-bills-and-payments-on-bill-pay](https://support.ramp.com/managing-bills-and-payments-on-bill-pay) — the needs-review and payment-queue surface referenced in the Gap Map tab
- [support.ramp.com/bill-pay-set-up](https://support.ramp.com/bill-pay-set-up) — approval policy and threshold configuration
- [support.ramp.com/employee-roles-and-permissions-on-bill-pay](https://support.ramp.com/employee-roles-and-permissions-on-bill-pay) — approval routing and role-based review

**Carried from the original project brief, not independently re-verified by
this repository's own research:** the claim that Ramp documents AI-generated
approval recommendations and full audit history. Treat those two specifically
as secondhand until someone checks them directly — the Gap Map tab's "Not
found in public docs" rows are the ones this project actually stands behind.

**Design references** (typeface and colour approximations, not confirmed
against an official Ramp brand guide — full caveat in [`DESIGN.md`](DESIGN.md)):
a public design-system write-up at
[oh-my-design.kr/design-systems/ramp](https://oh-my-design.kr/design-systems/ramp)
and Ramp's own marketing site. One source,
[designmd.co/d/ramp](https://www.designmd.co/d/ramp), returned a 403 when
fetched directly and could not be verified — its claims are not repeated here.

## 4. What has no source at all

Said plainly, because it's easy to let this blend into the cited claims above:
the five root-cause categories, the intervention catalogue in
[`src/interventions.py`](src/interventions.py), and the choice to model
concentration at the top-3-vendor level are all the author's product
judgement. They are reasonable starting points for a conversation with real
AP operators, not conclusions from one.

## 5. If you want to check a number yourself

```bash
make install && make data && make test
.venv/bin/python -c "
from src.loader import load_exceptions, load_bill_volume
from src.analytics import add_derived, baseline_metrics, root_cause_table
df = add_derived(load_exceptions(strict=False))
vol = load_bill_volume()
print(baseline_metrics(df, vol))
print(root_cause_table(df))
"
```

Every figure in `README.md` and `CASESTUDY.md` was produced by running
exactly this, against the bundled seed.
